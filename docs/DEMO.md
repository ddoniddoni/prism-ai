# Prism AI 데모 가이드

이 문서는 시연 절차와 기대 결과다. 이 순서로 실제 실행을 완료했다는 기록은 아니다.
2026-09-06 세션에서는 테스트와 브라우저 시나리오 실행을 보류했다.

## 준비

```bash
npm ci
AI_PROVIDER=mock AI_LIVE_ENABLED=false DATA_SOURCE=local PERSIST_ANALYSIS_HISTORY=false npm run dev
```

사용 데이터는 2024-09-01부터 2026-08-30까지의 합성 이커머스 데이터다.
기간 Preset은 시스템의 오늘이 아니라 Dataset의 마지막 완료일을 기준으로 해석한다.
따라서 시연 날짜가 달라져도 같은 조건의 분석을 설명할 수 있다.

## 대표 시나리오

| 순서 | 사용자 동작 | 확인할 결과 | 설명할 설계 |
| --- | --- | --- | --- |
| 1 | Home에서 `지난달 매출이 왜 감소했어?` 제출 | `매출 분석 결과`, 핵심 매출·추이·세그먼트·계산된 근거 | AI는 계획을 선택하고 코드가 값을 계산 |
| 2 | `모바일만 자세히 분석해줘.` 후속 질문 | `모바일 매출 분석 결과`, 모바일 조건과 기존 기간 유지 | Context Patch의 명시된 필드만 변경 |
| 3 | `작년 같은 기간과 비교해줘.` 후속 질문 | 모바일 Filter 유지, 비교 기준이 전년 동기로 변경 | 같은 Context에서 비교 조건만 변경 |
| 4 | 차트의 세그먼트 선택 후 `상세 분석` | 선택 조건으로 범위가 좁아진 분석 | 허용된 차원 Filter만 서버에서 검증·강제 |
| 5 | Filter 제거 또는 비교 Select 변경 | 현재 조건에 맞는 새 분석, 준비 중 이전 결과 유지 | 성공 응답과 요청 상태를 분리 |
| 6 | 편집 모드에서 차트 표시 형식 변경·삭제·Undo | 호환 표시 전환과 위젯 복원 | Zustand는 편집 상태만 저장 |
| 7 | History에서 저장된 분석 다시 열기 | 당시 조건·결과 복원 | 검증된 저장 응답을 사용하고 AI 재호출 없음 |

매출 하락의 주요 기여 Segment는 합성 데이터의 Mobile·Fashion 시나리오로 설명한다.
관측된 기여와 실제 인과관계는 구분하며, 숫자는 시연 화면의 계산 결과를 사용한다.

## 추가 화면 후보

- `지난달 매출의 디바이스별 구성을 보여줘.`: 일자별 누적 막대와 선택 근거
- `지난달 매출 집중도를 달력 히트맵으로 보여줘.`: 일별 집중도와 월간 요약
- `서울에서 산 제품들 판매량만 보여줘.`: 한국어 지역명과 원본 Filter 값의 분리
- `광고비 대비 성과를 보여줘.`: 합계가 아닌 비율 지표 ROAS

## 공개 전 확인할 항목

Desktop·Mobile, 키보드 탐색, 후속 질문 오류 후 기존 결과 유지, 편집 저장 복원과
History 재열기를 확인한 뒤 해당 결과와 날짜를 `PROGRESS.md`에 기록한다.
스크린샷·영상은 그 실행에서 얻은 실제 화면을 사용한다.

일일 한도는 Mock에도 적용된다. 기본값은 새 분석 10회이며 Cache Hit는 한도를
소비하지 않는다. 한도에 도달하면 화면의 안내를 따르고, 로컬 시연 준비에서만
환경 설정으로 한도를 조정한다. 공개 데모의 운영 제한을 검증 완료로 추정하지 않는다.
