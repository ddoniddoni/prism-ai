# 제품 완성도 점검 · 2026-09-06

## 판단 기준

Prism AI의 목적은 이커머스 질문을 검증된 분석 계획으로 바꾸고, 실제 조회 결과로
구성한 대시보드에서 비교·탐색·후속 분석을 이어가게 하는 것이다. 범용 챗봇이나
임의의 화면 생성기가 아닌, 근거를 확인할 수 있는 분석 작업 공간을 우선한다.

## 이번 개선

| 부족했던 부분 | 반영한 동작 |
| --- | --- |
| 무엇이든 질문할 수 있다는 안내와 제한된 데이터 범위의 차이 | 홈에 지원 지표·분류와 합성 데이터의 기준일 안내, 추천 질문을 동일한 열로 정렬 |
| 기간을 직접 바꿀 수 없음 | 기간 프리셋 9개와 직접 날짜 입력, 잘못된 날짜·역전 기간 검증 |
| 원래 질문에서 필터가 다시 추론될 수 있음 | 직접 조작한 기간·필터·비교 기준을 모든 Query에 강제하고 변경하지 않은 Context 보존 |
| 조합 변경 후 큰 빈칸, 측정 높이와 다른 고정 좌표 | 남는 열을 분배하고 짧은 열에 Insight 배치, 카드 경계를 맞추며 실제 높이로 다음 좌표 계산 |
| 위젯 복구를 위해 전체 초기화가 필요 | 숨긴 위젯별 복구 메뉴, 표시 형식·숨김을 보존하는 자동 정리, Undo 지원 |
| 다른 크기의 위젯 이동에서 겹침 가능 | 앞뒤 순서 이동 후 충돌하지 않게 다시 배치, 모바일은 버튼 이동 사용 |
| 일부 조회 실패와 빈 결과도 완료로만 표시 | 부분 성공·빈 데이터 상태 구분, 누락 조회와 Dataset 경고·실제 기간을 펼쳐 확인 |
| Insight의 근거가 개수로만 표시됨 | 계산식 설명·조회 기간·전체/비교/선택 항목 값을 펼쳐 확인, 100% 초과 기여도 해석 보완 |
| 결과를 화면 밖에서 활용할 수 없음 | 현재 분석의 조회 결과를 UTF-8 CSV로 다운로드. 원본 숫자·null·단위·필터·비교 기간 보존 |
| 버전 기록이 분석 결과보다 많은 공간을 차지 | 결과 아래 접이식 기록으로 이동, 요청 중 버전 변경 방지 |
| 오류 후 원래 질문 수정 동선 부재 | 질문 원문을 유지해 홈으로 돌아가는 링크 |
| 저장 실패가 성공 결과 표시를 방해할 수 있음 | 결과를 먼저 표시하고 저장 실패를 별도 안내 |

자동 정리는 사용자가 선택한 표시 형식과 숨김을 유지한다. 사용자가 직접 만든
배치는 자동으로 덮어쓰지 않는다. 초기화는 별도 기능이며 모든 편집을 되돌린다.
내용에 필요한 카드 안쪽 여백은 유지하고 카드 사이의 불필요한 빈 공간을 줄였다.

## 제거·축소한 표현

- 홈의 ‘무엇이든’ 문구를 실제 지원하는 매출·광고 성과 안내로 교체했다.
- 반복되던 내부 계산 엔진 설명을 줄이고 상세 조회 근거로 모았다.
- 위젯 ‘삭제’는 실제 동작에 맞게 ‘숨기기’로 표시한다.
- 모바일의 불필요한 세로 상태 배치와 항상 펼쳐진 버전 목록을 축소했다.
- 이전에 제거한 미구현 Library·Settings·알림·가짜 검색 기능은 다시 노출하지 않는다.

## 검증과 한계

- `npm run lint`, `npm run typecheck`, Mock/Local 환경의 `npm run build` 실행 결과는
  `PROGRESS.md`에 기록한다.
- Playwright CLI로 실제 로컬 브라우저를 조작했다. 테스트 러너는 실행하지 않았다.
- 1440px Desktop과 375px Mobile을 확인했다. 추천 질문 분석, 최근 7일 전환,
  2026-06-01 ~ 2026-06-30 직접 기간 분석, 위젯 숨김·개별 복구·자동 정리,
  CSV 다운로드를 확인했다. 모바일 문서 너비와 Viewport는 모두 375px였다.
- 다운로드 CSV는 14개 열의 일관된 행 구조이며 조회 기간과 원본 집계값을 포함한다.
- 개발 도중 발견한 동일한 React Key로 인한 중복 도구 렌더링을 수정했다.
  새로고침 후 확인한 흐름에서 같은 오류가 재발하지 않았다.
- 회귀 테스트 코드를 추가·갱신했지만 사용자 요청에 따라 Unit/E2E 테스트,
  `npm run check`, react-doctor는 실행하지 않았다.
- 브라우저 점검은 Mock/Local이다. 실제 Gemini·원격 DB·여러 브라우저의 전체 동작을
  검증했다는 의미는 아니다. 화면 측정·CSV 산출물은 Git에서 제외한다.

## 다음 우선순위

1. **요청 취소와 진행 상태**: 공유 중복 요청의 다른 구독자를 취소하지 않는 설계로
   Browser → Route → Provider 취소를 전달하고 실제 서버 단계 이벤트를 표시한다.
2. **캐시 정확성**: 실제 Dataset Version과 Model ID를 캐시 키에 반영하고 운영 시
   여러 서버 인스턴스의 제한·캐시 일관성을 별도로 설계한다.
3. **운영 데이터 안내**: 홈·Dashboard Shell의 현재 Local Dataset 안내를 실제 선택된
   Repository Metadata와 일치시키고 원격 데이터 연결의 오류·갱신 시각을 표시한다.
4. **상태별 전체 회귀 검증**: 테스트 재개 시 Partial·Unsupported·Empty·Storage 실패,
   버전 복원, 편집 보존과 다양한 화면 크기를 실행해 공개 준비 상태를 판정한다.
5. **공유·외부 데이터**: 현재 브라우저 기록을 다른 사람에게 공유하는 URL로 오해하지
   않도록 저장·권한·보존 정책을 먼저 설계한다. 공개 링크·협업·PNG/PDF는 후속 범위다.

인증·결제·설정 화면을 채우기 위해 새 기능을 만드는 것보다 위의 분석 정확성과
복구 흐름을 먼저 완성한다. 이 문서는 전체 제품이 완벽하게 검증됐다는 완료 선언이 아니다.
